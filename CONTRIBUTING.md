# Contributing

Danke, dass Du helfen möchtest! Dieses Projekt ist offen für Beiträge. Bitte beachte die folgenden Regeln und Schritte, damit deine Mitwirkung schnell und unkompliziert angenommen werden kann.

1) Issues
- Öffne zuerst ein Issue, bevor du grössere Änderungen implementierst. Beschreibe Problem oder Vorschlag kurz und klar.
- Nutze prägnante Titel und füge reproduzierbare Schritte / Beispiele an.

2) Fork, Branch, Pull Request
- Forke das Repository und arbeite in einem Feature‑Branch mit sprechendem Namen (z. B. `fix/README-typo` oder `feat/add-license`).
- Committe kleine, thematisch zusammenhängende Änderungen.
- Push den Branch zu deinem Fork und erstelle einen Pull Request (PR) gegen `iki1uc/error404:main`.

3) Commit‑Nachrichten
- Schreibe klare Commit‑Nachrichten, z. B.:
  `fix: correct typo in 404.html`
  `chore: add LICENSE and NOTICE`
- Für grössere Änderungen kannst du das format `type(scope): message` nutzen (in Anlehnung an Conventional Commits).

4) Code‑Standards & Minimaler Check
- HTML: UTF‑8, gültiges HTML5, Titel (`<title>`) sollte kurz sein.
- JS: Verwende `const` / `let` statt globalen Variablen, benutze schlanke Funktionen und dokumentiere APIs mit Kommentaren.
- Entferne niemals die sichtbare Branding‑Zeile „© iki1uc wieimmer" auf öffentlichen Seiten.

5) Lizenz & Branding
- Dieses Projekt steht unter der MIT‑Lizenz (siehe LICENSE). Durch einen Beitrag erklärst du dich damit einverstanden, dass dein Code unter der gleichen Lizenz genutzt werden kann.
- Der sichtbare Branding‑Hinweis „© iki1uc wieimmer" soll in öffentlichen Darstellungen erhalten bleiben.

6) PR‑Review
- PRs werden durch die Maintainer geprüft und kommentiert. Bitte reagiere freundlich auf Review‑Kommentare und passe Änderungen entsprechend an.

7) Sonstiges
- Wenn du sensible Daten (z. B. Passwörter, API‑Tokens) findest, melde das sofort per Issue, aber poste keine sensiblen Inhalte in Issues oder PRs.

Vielen Dank für deinen Beitrag!
